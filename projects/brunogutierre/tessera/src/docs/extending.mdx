# Extending Tessera

Theme packages and apps restyle Tessera from the outside, without forking it. These hooks are the **public styling API**: they follow semantic versioning, so a rename is a breaking change. Everything else in the rendered markup, including the internal class names, may change in any release.

| Hook             | Example                                              | Use it for                                                           |
| ---------------- | ---------------------------------------------------- | -------------------------------------------------------------------- |
| Semantic tokens  | `--tes-color-primary`                                | A whole theme (see [Theming](?path=/docs/foundations-theming--docs)) |
| Component tokens | `--tes-button-radius`, `--tes-checkbox-mark`         | One component, everywhere or in a subtree                            |
| Host class       | `.tes-card`                                          | Selecting a component                                                |
| State attributes | `[data-variant='primary']`, `[aria-expanded='true']` | Styling a variant or a state                                         |
| Parts            | `[data-tes-part='header']`                           | Styling an element inside a component                                |

```css
@layer my-theme.decor {
  [data-tes-theme='christmas'] .tes-card [data-tes-part='header'] {
    background: var(--my-garland) top / auto 0.75rem repeat-x;
  }
}
```

Component styles use Angular's emulated encapsulation, which only scopes Tessera's own rules: global CSS reaches every part. Put your rules in a cascade layer declared after Tessera's, or leave them unlayered, and they win without `!important`.

## Tokens for native controls

Checkboxes, radios, switches and sliders are `<input>` elements, which cannot carry `::before` or `::after` in every browser. Their visuals are images you can replace:

| Token                                       | Default                | Notes                                                     |
| ------------------------------------------- | ---------------------- | --------------------------------------------------------- |
| `--tes-checkbox-mark`                       | Check mark             | Mask image: only its shape counts, the color is the fill  |
| `--tes-checkbox-mark-indeterminate`         | Dash                   | Mask image                                                |
| `--tes-switch-knob`                         | Round knob             | Background image of the unchecked knob, sized as the knob |
| `--tes-switch-knob-checked`                 | `--tes-switch-knob`    | Background image of the checked knob                      |
| `--tes-slider-filled`, `--tes-slider-empty` | Primary, strong border | Track colors                                              |
| `--tes-slider-thumb-image`                  | `none`                 | Image drawn on the thumb, at 80% of its size              |

To decorate around a native control, style its wrapper (`label[tes-choice]`, `tes-form-field`) instead.

## Rules for decoration

- Keep decoration out of the layout: position it absolutely inside the component, with `pointer-events: none`, so sizes and target areas do not change.
- Use `content: ''` in pseudo-elements: screen readers read generated text.
- Never carry information through decoration alone, never cover the focus ring, and stop animations under `prefers-reduced-motion: reduce`.
- Hide decoration under `forced-colors: active` and in print.
